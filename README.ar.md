# 🌱 منصة سنابل التعليمية | Sanabil Educational Platform

**منصة تعليمية بواجهة عربية، تساعد الطلاب في فلسطين على الوصول إلى مصادر تعليمية منظّمة.**

[English](README.md) | **العربية**

## نبذة عن المشروع

سنابل منصة تعليمية تهدف إلى تسهيل وصول الطلاب في فلسطين إلى المصادر التعليمية المعتمدة، من خلال واجهة عربية واضحة ومتجاوبة. يستطيع الطالب استعراض الصفوف، واختيار المادة، ثم الانتقال إلى وجهات Google Drive التعليمية المرتبطة بها. وتتيح لوحة إدارة محمية تنظيم المحتوى والتحكم في ظهوره.

**نطاق المنصة:** تنظّم سنابل الروابط المؤدية إلى وجهات Google Drive المعتمدة، ولا تستضيف الملفات الموجودة فيها أو تفهرسها أو تنسخ محتواها.

## المميزات

### تجربة الطالب
- واجهة عربية متجاوبة تدعم اتجاه الكتابة من اليمين إلى اليسار (RTL).
- استعراض الصفوف ثم المواد الدراسية عبر واجهات API عامة.
- صفحات مخصصة للمواد على المسار `/subjects/[slug]` تتضمن روابط Google Drive المعتمدة.
- تنقل سريع بين المواد ورسائل واضحة عند عدم توفر محتوى.
- إعلانات مرتبة وقابلة للجدولة، مع صور وروابط اختيارية.
- وسائل تواصل مباشرة عبر الهاتف وWhatsApp.

### لوحة الإدارة
- تسجيل دخول للإدارة وجلسة مصادقة عبر ملفات تعريف الارتباط، مع لوحة تحكم محمية.
- إضافة الصفوف والمواد وتعديلها وتفعيلها أو تعطيلها وتغيير ترتيبها.
- إدارة الروابط التعليمية المعتمدة، وحالات ظهورها وترتيبها داخل كل مادة.
- إنشاء الإعلانات وتعديلها وجدولتها وتفعيلها وترتيبها، مع إمكانية رفع الصور.
- عرض أعداد المحتوى في لوحة التحكم وتعديل بيانات حساب المدير وكلمة المرور.

## هيكلية المشروع

يضم المستودع تطبيقين ضمن مشروع واحد يستخدم npm workspaces:

```text
sanabil-educational-platform/
├── frontend/          # موقع الطلاب وواجهة الإدارة باستخدام Next.js
├── backend/           # واجهة Express وPrisma والترحيلات
├── docs/              # توثيق التشغيل والنشر
├── package.json       # أوامر المشروع الرئيسية
├── README.md          # التوثيق الإنجليزي
└── README.ar.md       # التوثيق العربي
```

تستخدم الواجهة الأمامية واجهات API عامة لعرض محتوى الطلاب، وواجهات محمية لإدارة المحتوى. تخزّن MySQL بيانات الصفوف والمواد والروابط والإعلانات وحسابات الإدارة. وتظل الملفات التعليمية نفسها مستضافة في Google Drive بصورة مستقلة عن سنابل.

## بدء التشغيل محليًا

### المتطلبات
- Node.js بالإصدار **20.9 أو أحدث**
- MySQL **8.4 LTS**
- npm

### 1. تثبيت الاعتماديات

نفّذ الأمر التالي من جذر المستودع:

```bash
npm install
```

### 2. إعداد متغيرات البيئة

انسخ `backend/.env.example` إلى `backend/.env`، وانسخ `frontend/.env.example` إلى `frontend/.env.local`.

استبدل القيم التجريبية بإعدادات بيئتك المحلية. تحتاج الواجهة الخلفية إلى رابط اتصال MySQL، وعنوان الواجهة الأمامية، وقيمة قوية لـ `JWT_SECRET` لا تقل عن 32 حرفًا. اضبط `NEXT_PUBLIC_API_URL` على أصل عنوان الخادم الخلفي، مثل `http://localhost:4000`، **من دون** إضافة `/api` في نهايته.

لا ترفع بيانات الدخول أو ملفات البيئة التي تحتوي على أسرار إلى المستودع.

### 3. تجهيز قاعدة بيانات التطوير

استخدم **قاعدة بيانات تطوير محلية**، وليس قاعدة الإنتاج:

```bash
npm run prisma:generate --workspace backend
npm run prisma:migrate --workspace backend
npm run prisma:seed --workspace backend
```

يهيّئ أمر Seed بيانات الإدارة والمحتوى التعليمي أو يوفّقها مع الإعدادات الموجودة. اضبط بيانات حساب الإدارة الأولية قبل تشغيله.

### 4. تشغيل التطبيقين

شغّل كل أمر في نافذة Terminal منفصلة:

```bash
npm run dev:backend
```

```bash
npm run dev:frontend
```

- الواجهة الأمامية: `http://localhost:3000`
- واجهة API الخلفية: `http://localhost:4000`
- فحص حالة الخدمة: `http://localhost:4000/api/health`
- تسجيل دخول الإدارة: `http://localhost:3000/admin/login`

## نظرة على واجهات API

تشمل الواجهات العامة:
- `GET /api/public/grades`
- `GET /api/public/subjects?grade=<slug>`
- `GET /api/public/subjects/:slug/drive-links`
- `GET /api/public/announcements`

واجهات المصادقة:
- `POST /api/auth/login`
- `POST /api/auth/logout`
- `GET /api/auth/me`

توجد واجهات الإدارة المحمية تحت `/api/admin/` لإدارة الصفوف والمواد وروابط Drive والإعلانات والملف الشخصي وبيانات لوحة التحكم. ينشئ تسجيل الدخول ملف تعريف ارتباط HttpOnly للجلسة، ولا يعيد JWT ضمن استجابة JSON.

## الاختبارات وجودة الكود

شغّل أوامر التحقق التالية من جذر المستودع:

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

تشغّل هذه الأوامر السكربتات ذات الصلة في تطبيقَي الواجهة الأمامية والخلفية. يجب التحقق من نجاحها في بيئة التنفيذ الحالية؛ ولا يعني هذا التوثيق أنها شُغّلت أثناء تعديل README.

## النشر والتشغيل

تُنشر الواجهة الأمامية باستخدام Vercel، بينما تعتمد آلية نشر الواجهة الخلفية على GitHub Actions وسكربت نشر مقيّد على VPS. **قد تؤدي التحديثات على فرع `main` إلى تشغيل النشر الإنتاجي**؛ لذلك يجب مراجعة التغييرات والتحقق منها قبل الدمج.

توجد تفاصيل ترحيلات قاعدة بيانات الإنتاج، والنشر، وملفات صور الإعلانات الدائمة، والنسخ الاحتياطي، والاستعادة في [توثيق النشر](docs/DEPLOYMENT.md). لا تشغّل `prisma migrate dev` على قاعدة بيانات الإنتاج.
